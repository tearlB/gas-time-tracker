# 週間予定の予測ルール案

## 表示は２種類にする

週カレンダーで見る時間バーは **予定** と **実績** の２種類だけにする。

- **予定**：置いた予定時間を日ごとに割り当てる。完了した予定は残工数を未来へ予約しない。
- **実績**：日次入力で記録した実作業時間。予定バーの位置や量を書き換えない。

「当初の枠」と「再配置」は使わない。先行や実績の差で予定を別の日へ詰め替えず、置いた予定時間をその予定のバーとして残す。完了した予定だけは、残工数を未来へ予約しない。

## 予測に使う値

内部では次の３値を分ける。

| 値 | 意味 |
| --- | --- |
| `P0` 当初予定 | 最初に決めた予定工数。予定超過の比較基準 |
| `E` 着地見込み | 現時点での完了までの総工数見込み。初期値は `P0`、必要なら更新 |
| `A` 実績 | 日次実績の合計 |

未完了の残工数 `R` は `max(0, E - A)`。完了済みなら `R=0`。`A >= E` なのに未完了の場合は、残りが本当に 0h とは決めつけず「見込みを更新」とし、未来へは再予約しない。ユーザーが更新した `E` から `A` を引き、残工数を配り直す。

例：当初予定 `P0=8h`、実績 `A=10h`、着地見込み `E=13h` なら、超過は `2h`、残工数は `3h`。未来には `3h` だけ配分する。実績超過分 `2h` は未来へ持ち越さない。

## 日ごとの割り当てと持ち越し

1. 過去日の予定と実績を履歴として保つ。新しい配分は今日以降に行う。
2. 未完了タスクの予定時間を、優先順位、開始日、日上限、日別指定に従って割り当てる。実績が予定より少なくても、その予定枠は後続タスクへ渡さない。同じ予定を容量から二度引かない。
3. カレンダー予定と取り込み済み実績も二重計上しない。実績がその日の稼働枠を超えたら超過を示し、その日には追加の未来予定を置かない。
4. 週末に割り当て切れなかった `R` だけを次週へ持ち越す。`R` が未確定のタスクは行を残して「見込みを更新」と表示し、架空の時間バーや完了日を作らない。
5. 完了チェックは `R=0` にする。未来の予定と数値付き持ち越しは 0h。別の「当初の枠」は残さない。

## 期待する例

| 状況 | 表示・予測 |
| --- | --- |
| 当初 8h、実績 10h、着地見込み 13h、未完了 | 予定超過 2h。未来に 3h を割り当てる |
| 当初 8h、実績 10h、着地見込み未更新、未完了 | 「見込みを更新」。未来の架空の予約・数値付き持ち越しは作らない |
| 当初 8h、実績 3h、完了 | 未来予約 0h。実績だけを残す |
| 稼働 8h の日に実績 10h | 実績超過 2h。追加の予約は置かない |

## 実装上の注意

- 現在の予測処理は実績が予定を超えていても、初週の未完了予定に予定工数全量を再配分する。`remaining` は 0h なのに `overflowHours` は正になり、そのまま持ち越し表示される。
- 翌週への継続は残工数ではなく未完了状態だけで決まり、残り 0h でも予定行を作る場合がある。
- 日別の「当初の枠」と、空いた時間への「再配置」はしない。予定バーは配分した予定時間そのものにする。
- 実績超過のタスクに対し、現在は着地見込み `E` を入力・保存する専用欄がない。予測を直す実装では `E` を保持し、予定編集時に当初値へ無条件に戻さないこと。
