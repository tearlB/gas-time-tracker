# まとめて工数管理さん

月・週・日の予定と実績を、一つのカレンダーで管理する Google Apps Script (GAS) の PWA です。

## 主な機能

- 単一カレンダー: 日・週・月を切り替え、月から週、週から日へ掘り下げて操作。月は Backlog のようなガント表示（見るだけ）で、プロジェクトごとにまとめ、予定名・プロジェクト・状態・予定日のずれで絞り込める
- 前後の期間の確認: 選択した週の前後1週（計21日）、選択した月の前後1か月（計3か月）を同じタイムラインで表示。横スクロールだけで前後の予定・実績を確認でき、「選択週へ戻る」「選択月へ戻る」で指定期間の先頭へ戻る。前後の週だけにある予定は閲覧用で、選択週の保存データには追加しない。週のカレンダー予定・稼働時間の編集は選択週を対象とする。日・週・月の対象日付はそれぞれ独立
- 予定と実績: 予定は開始日〜終了日の期間（ガントのバー）と予定工数で押さえ、日ごとの予定時間は持たない。日次の「課題1 調査」のような子タスク工数を親の実績へ集計し、バーの上に実績だけを表示
- 週次カレンダー: Googleカレンダーの予定と週予定を同じ週グリッドで確認し、空きマスから予定を追加・編集
- プロジェクト管理: プロジェクト本体を恒久保存し、月ごとの予定稼働時間・状況説明・1人月に対する配分と残りを確認。予定稼働は時間のほか割合（50%・3割・1/2）でも入力でき、割合は月の稼働時間（1人月）に対する割合なので、他のプロジェクトの固定時間を変えても変わらない
- 今日の実績パネル: ヘッダーのアイコン（キー A）から、どの画面でも今日の実績を入力できる。日次画面の「今日」の行をそのまま使い、時間・完了・計測・削除・プロジェクト・名前の変更・並べ替え・課題の追加は日次画面と同じ処理と保存で行う。日次画面で今日以外の日を開いているときは使えず、「今日の日次画面を開く」を案内する
- ショートカットキー: D（日）・W（週）・M（月）・P（プロジェクト）・T（今日へ移動）・A（今日の実績パネル）。設定の「表示・操作」でキーを変更・解除でき、同じキーを複数の操作には割り当てられない。まとめてオフにもできる
- 週・月の「いま」の線: 週・月タブのタイムラインに、今日の列を時刻に合わせて左から右へ進む青い縦線を表示（1分ごとに更新）。月タブでは予定にカーソルを合わせると、クリックで開く週と日を枠で強調し、説明を出す
- Google Tasks 連携: 設定モーダルで連携のオン・オフ、同期先、自動同期を設定
- レスポンシブUI: デスクトップとスマートフォンで同じ操作を利用可能

## 開発対象

- GAS のウェブアプリ: [`gas/`](gas/)
- スプレッドシート: 選択した管理フォルダ内の年次ファイルだけを正本として利用
- PWA: `gas/index.html` と `gas/sw.html`
- 画面の編集元: `ui/` の HTML・CSS・JavaScript。`npm run ui:build` で `gas/index.html` を生成
- 週/月予実の基盤: [`gas/budget.gs`](gas/budget.gs)
- カレンダー稼働時間・予定タスク: [`gas/planning.gs`](gas/planning.gs)
- スプレッドシート構造の自動修復: [`gas/storage_schema.gs`](gas/storage_schema.gs)

## 初回セットアップ

1. GAS 用の依存関係をインストールする。

```bash
npm run gas:install
```

2. 初回だけ Google アカウントでログインする。

```bash
npm run gas:login
```

新規ログイン時の認証情報は、WSLから実行している場合はWindowsユーザーフォルダ（`C:\Users\<ユーザー名>\.clasprc.json`）に保存されます。WSL以外ではプロジェクト直下の `.clasprc.json`（git 管理外）を使います。`gas:create`・`gas:push`・`gas:deploy` では保存済みの認証情報を自動で使います。`npm run gas:login` を明示的に実行した場合は、保存済みでも省略せず再認証します。

`gas:login` は Apps Script の操作（push・deploy など）に必要な権限だけでログインします。clasp 標準のログインは Google Cloud の権限も求めるため、Google Workspace の「Google Cloud セッション制御」により一定時間ごとに再ログイン（`invalid_rapt`）が必要になるのを避けるためです。`clasp logs` など Google Cloud の権限が要るコマンドを使う場合は、`npm run gas:login -- --clasp` で clasp 標準のログインをしてください。

Windowsユーザー名とWSLユーザー名が異なる場合だけ、`GAS_CLASP_AUTH_FILE` で認証ファイルのパスを上書きできます。`.clasprc.json` にはOAuthのrefresh tokenが含まれるため、OneDrive配下ではない、他人が読めない場所に保管してください。

3. 新しいスタンドアロン GAS ウェブアプリプロジェクトを作成する。

```bash
npm run gas:create
```

既存の GAS プロジェクトを使う場合は、[`.clasp.json.example`](.clasp.json.example) を `gas/.clasp.json` にコピーし、`scriptId` を設定してください。

4. `gas/` の内容を GAS プロジェクトへ反映する。

```bash
npm run gas:push
```

GAS エディタでウェブアプリとしてデプロイすると、PWA として利用できます。更新時は `gas:push` の後に新バージョンをデプロイしてください。

## 公開（固定のURL）と前の版への戻し方

- `npm run gas:push`：開発用（`/dev` の URL、最新のコードがそのまま動く）に反映します。
- `npm run gas:deploy [-- "版の説明"]`：最新のコードを送り、版を1つ作って、固定の公開用デプロイ（`/exec` の URL）をその版に更新します。初回だけ新しいデプロイを作り、その ID を `gas/deployment-id.txt` に保存します。2回目以降は同じ URL のまま中身だけが新しい版になります。コミットしていない変更があるときはデプロイせずに止まります。公開したら、そのコミットに `deploy-v<版の番号>` のタグを付け、ブランチとタグを GitHub（リモート `github`。`GAS_GIT_REMOTE` で変更可）へ push します。`gas:push` は GitHub へは送りません。
- `npm run gas:restore -- deploy-v<版の番号>`：本番を前に公開した版の内容に戻します。履歴は消さずに「その版の内容に戻す」コミットを作り、テストが通れば `gas:deploy` で新しい版として公開します（本番と GitHub がずれません）。戻すのはアプリの中身（`gas/`・`ui/`・`tests/`）だけで、デプロイ用のスクリプトは今のものを使います。戻せる版は `git tag -l 'deploy-v*'` で確認できます。
- `npm run gas:rollback -- <版の番号>`：急ぎのときに、公開用デプロイを GAS に残っている前の版へすぐ切り替えます。GitHub の内容とはずれるので、落ち着いたら `gas:restore` か修正のデプロイでそろえてください。番号なしで実行すると版の一覧を出します。

## GAS 側で必要な設定

- タイムゾーン: `Asia/Tokyo`
- 高度なサービス: Google Sheets API v4、Google Calendar API v3、Google Tasks API v1
- ウェブアプリ: ユーザーとして実行、ドメイン内アクセス

設定は [`gas/appsscript.json`](gas/appsscript.json) に入っています。Google Tasks API は高度なサービスとして追加されています。標準の Google Cloud プロジェクトを使う場合は Google Cloud Console でも Google Tasks API を有効にしてください（デフォルトの Apps Script プロジェクトではサービス追加時に有効になります）。権限は Google Tasks 設定画面を開いたときに承認します。

## データ構成

画面上部の「保存先」からDrive内の親フォルダを階層表示で選び、確認後に管理フォルダと年ごとのスプレッドシートを作成します。新しい年のファイルも作成前に確認します。通常の読込では、設定済みの年次ファイル以外を検索・参照しません。すでに年次管理中の保存先を変更する場合は、各年度のファイルを同じ年度のまま新しい管理フォルダへコピーします。

各年ファイルでは、月別の日次シートを実績の正本とし、次のシンプルな構造で予定と設定を保存します。

- `予実計画`: 週・月の親予定を1予定1行で保存
- `予定タスク`: 親予定に属するサブタスクを1サブタスク1行で保存
- `プロジェクト`: 月に依存しないプロジェクト本体を保存
- `プロジェクト月次`: 対象月ごとの予定稼働時間と稼働状況説明を保存
- `YYYY-MM`: 日次の実績を保存
- `稼働設定` / `カレンダー除外`: 必要な場合だけ作成

親予定とサブタスクは `予定ID` で結びつけます。以前の列順・列名、旧形式の課題欄、重複や欠落したIDがあっても、読み込み時にヘッダー名を基準に自動修復します。`予実計画` の `完了` は空欄なら日次・サブタスクから自動判定、`TRUE` なら完了、`FALSE` なら未完了として自動判定を上書きします。スキーマを変更するときは `gas/storage_schema.gs` のバージョンを上げ、既存データを正規構造へ移行します。未使用の `週次報告` シートは自動的に削除対象になります。

週予定は週間カレンダーから追加・編集します。サブタスクは親タスク名の直下にインデントして表示し、丸い完了表示と開閉矢印でGoogle Tasksに近い階層表示にしています。Googleカレンダーの予定は週次カレンダーに表示します。設定モーダルの「カレンダー」から読み込むカレンダーを複数選べます。カレンダーどおりに実施しない予定は除外でき、予定時間と実績時間が違う場合は予定全体を「今日だけ」として扱います。除外した予定は稼働時間から外します。日付をクリックするとその日の日次画面を開き、そこで実績を記録します。今日の実績は、どの画面からでも「今日の実績パネル」で記録できます。日次は「課題1 調査」のように親名で始まる子タスクとして結びつけ、年をまたぐ週は複数年ファイルの日次工数を実績として集計します。

予定は `予実計画` の `開始日`・`終了日` で期間を持ち、週をまたいで表示します（保存先は登録した週の行のまま）。週の画面には、期間がその週にかかる予定と、その週に実績がある予定を出します。開始日より前の実績は「前倒し」、終了日より後の実績は「期限超過」として帯の外に色を変えて表示します。未完了のまま終了日を過ぎた予定は、今週以降の画面に「期限切れ」として残ります。終了日が空の旧データは、登録した週の月曜（または開始日）からその週の金曜までの予定として扱い、以前の持ち越しと同じく実績がある未完了の予定だけを次の週に残します。予定ダイアログで開始日・終了日を両方空にすると「期間未定」として登録でき（シートの `終了日` は `未定`）、完了するまで登録した週以降の画面にバーなしで出ます。「予定を追加」ボタンからは日付が空の状態で開きます。日次入力の候補には、これから始まる予定（4週先まで）も「これから」として出し、前倒しで実績を記録できます。詳しくは [`docs/plan-period-gantt.md`](docs/plan-period-gantt.md) を参照してください。

全画面共通の「設定」から「Google Tasks」タブを開き、連携のオン・オフと同期先のタスクリストを選びます。既存リストを選択するか、新しいリストを作成できます。連携は初期状態でオフです。「今すぐ同期」は選択月の進行中・超過課題を追加・更新します。自動同期も設定から個別にオンにでき、オンの場合はアプリ起動時と日次・予定・プロジェクトの保存後に同期します。アプリを閉じている間の定期同期は行いません。自動同期をオフにしている間は手動同期だけです。同期先リストはユーザーごとに選択し、同じ課題は次回同期時に同じタスクを更新します。同期はアプリから Google Tasks への一方向で、アプリ上で進行中の課題は同期のたびに Google Tasks 側で未完了に戻ります。連携をオフにしても既存のGoogle Tasksは削除せず、アプリ側で進行中でなくなった課題もGoogle Tasks側に残します。設定の「表示・操作」では、保存バー、課題追加、予定追加、プロジェクト登録ボタンの表示とショートカットキーを切り替えられます。日次の「課題を追加」をオフにすると、今日の実績パネルの「週の課題から選ぶ」も隠れます。

日次入力の「週予定から追加」には、対象日の週予定だけを親として表示します。今日の作業名を入れると「課題1 調査」のような日次タスクが追加され、「調査、テスト」とカンマ区切りにすると複数追加できます。空のタスクや月予定・カレンダー予定からの新規作成はできません。未完了の日次タスクは、状態を「完了」にするか累積工数が予定総工数へ到達するまで翌日以降へ自動表示されます。日次に保存した子タスクの工数は、親の週予定の実績へ反映されます。今日だけの作業（予定にない作業）は予定を持たないため、日次の「予定工数」の列は本日実績と同じ値になり（実績を変えると一緒に変わります）、残り工数は0です。

## ローカル確認

```bash
npm run ui:build
npm test
npm run preview
```

画面の変更は `ui/index.template.html`、共通スタイルの `ui/styles.css`、画面別スタイルの `ui/views.css`、機能別の `ui/*.js` に加えてください。Material Web と GSAP の読み込みは `ui/vendor.js`、共通の動きは `ui/motion.js` にあります。アイコンは Material Symbols Outlined を Google Fonts から必要な名前だけ読み込みます。アイコンを追加する場合は `ui/index.template.html` の `icon_names` に名前を追加してください。`gas/index.html` は esbuild でライブラリを内包する GAS 配信用の生成物です。最初にルートで `npm install` を実行してください。`npm test` は生成物が編集元と一致するかも確認します。`gas:push` と `preview` は生成を自動実行します。

`npm run preview` の後に `http://127.0.0.1:4173` を開くと、GAS APIをモックしたカレンダー画面を確認できます。今週と直前の2週は予定・実績・会議が入った保存済み週、それより先の週は未保存のまま会議だけ入っています。

バックグラウンドのプレビューは `npm run preview:stop` で停止できます。

### ブラウザ内の控えとアカウント

画面の表示状態・タイマー・表示設定などはブラウザの localStorage に控え、Googleアカウントごとに分けて保存します（キーの末尾にアカウント固有の識別子を付けます）。同じブラウザで複数のアカウントを使っても控えが混ざりません。分離前の控えは、最初に開いたアカウントへ引き継いで元の場所から消し、別のアカウントには引き継ぎません。識別子が取れないときは従来のキーを使います。

### 課題URL

予定の課題URL（`予実計画` の `課題URL`）には、BacklogのHTTPSの課題ページ（`https://スペース名.backlog.jp/view/PROJ-123` など。`backlog.com`・`backlogtool.com` も可）だけを保存します。それ以外のURLや500文字を超えるURLは空欄として保存します（`gas/budget.gs` の `budgetIssueUrl`）。

### Backlogから週予定へ追加する

設定 → Backlog でスペースURLとAPIキーを登録し、「接続を確認して保存」を押します。週タブの「Backlogから追加」で、自分が担当する未完了課題を選んで予定に追加できます。件名・課題URL・予定工数・開始日・期限を引き継ぎます。工数未設定は0時間、日付未設定は期間未定として追加するので、取り込み後に予定を確認してください。取り込み済みの課題は選択できず、一覧の下側に「取り込み済み」として出します。

取り込み済みの課題は、予定工数と期間（開始日・期限）がBacklogと違うとき「Backlogと違います: 予定工数 8h → 10h」のように差分を表示し、「Backlogの値を反映」で予定へ反映できます（サブタスクの予定工数の合計がBacklogの予定工数を超えるときは反映せず、先にサブタスクを直すよう案内します）。別の週で取り込んだ予定は、その週を開いて確認してください。Backlogの日付が未設定の場合、期間は変更しません。

接続確認のときに本人のBacklogユーザーIDも控え（UserProperties）、課題を取得するたびの本人情報の問い合わせを省いています。接続設定を削除するとIDも消えます。設定が未登録のまま「Backlogから追加」を開くと、エラーにせず設定の「Backlog」タブを開いて案内します。

APIキーは実行ユーザー本人のUserPropertiesだけに保存し、画面へは登録の有無を返します。APIへの認証はヘッダーを使います。接続設定は設定画面から削除できます。

実装で参照した公式仕様： [認証](https://developer.nulab.com/docs/backlog/getting-started/)、[課題一覧](https://developer.nulab.com/docs/backlog/api/2/get-issue-list/)。
